# LetoAPI: замороженный ABI

`LetoAPI` — контракт между консолью и играми. Игра несёт собственную копию `LetoCore`
и обращается к хосту только через `leto_api_v1`; ABI-несовместимость ломает уже
собранные `.so`/`.dll`.

## Правила

- Совместимое добавление — новая функция в конец таблицы версии, новый тип в отдельном
  заголовке. Несовместимое — новая версия (`LetoAPI_V2`), не правка `V1`.
- Существующие поля структур не переставлять, не менять тип, не удалять: layout и
  смещения фиксированы. Новое — только в конец, с явным заполнением нулями/дефолтами.
- Заголовки `V1` не удалять и не «причёсывать»: старые игры собираются против них.
- `AppBinHeader` и `AppEvent` — часть ABI: менять только через новую версию.
- `LetoAPI`, `LetoCore`, `LetoOS` остаются `STATIC` (кроме `WIN32` с `LETO_PATH`).
  Перевод на `SHARED` — архитектурное решение, а не деталь.

## Проверка

1. Собрать цепочку (`leto-build`) — `LetoAPI` первым, затем `LetoCore`, `LetoOS`,
   `leto-console`; иначе проверится старый заголовок.
2. Собрать игру против нового API (`leto-new-game` / `game-template`), запустить
   headless (`leto-run-game`).
3. Сравнить символы/структуры с предыдущей версией, если правка касается layout:
   изменение размера публичной структуры видно только у потребителя.

## Оформление

Несовместимое изменение = отдельный issue и `docs/adr/NNNN-*.md` с причиной, а не
попутная правка в другой задаче. В PR перечислить, что именно изменилось в контракте.
