# Локальный запуск

## Headless (без дисплея, для проверок и CI-подобных прогонов)

```sh
SDL_VIDEODRIVER=dummy LETO_PATH="$LETO_PATH" \
  ./build/linux-st7735-debug/leto-console --user 0 \
  --game "$LETO_PATH/Apps/linux-debug/Battleship/libBattleship.so"
```

## Где загрузчик ищет игры

Каскад, первый найденный выигрывает: `<cwd>/Apps/<preset>/`, `<cwd>/Apps/`,
`$LETO_PATH/Apps/<preset>/`, `$LETO_PATH/Apps/`. Пресет берётся из
`-DLETO_PRESET_NAME`, поэтому `Apps/win-debug/` на Linux не ищется.

## Нюансы, проверенные на практике

- `--game <путь>` отменяет сканирование и грузит `.so` напрямую; путь канонизируется,
  потому что относительное имя `dlopen` разрешает только при `cwd` = каталог библиотеки.
- Точка входа — переменная `__leto_exec_info__`, а не функция `Init`:
  `dlsym(handle, "Init")` вернёт `NULL`.
- `--game` обрабатывается внутри `if (--user)` в `Core/Src/Application/System.cpp`,
  а сцены `GAMES_CENTER`/`APP_SCENE` регистрирует `InitUserScenes()`, которую вызывает
  только успешный вход. Без аккаунтов `--game` молча висел в AUTH; теперь `--user`
  заводит тестовый аккаунт, если список пуст.
- `server.eeprom` в `.gitignore`: аккаунт живёт только в рабочей копии. Чистый клон
  стартует с первичной настройки.

## Что считать результатом

Не «процесс не упал», а конкретный наблюдаемый эффект: сцена/экран, лог, код возврата.
Процесс, висящий без вывода, — не успешный запуск.
