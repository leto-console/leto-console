# Синхронизация клонов

Репозитории проекта — независимые клоны, не подмодули. Ничто их не синхронизирует:
клон, выданный вместе с окружением, может отставать, при этом рабочее дерево
выглядит исправным.

## Проверить и подтянуть

```sh
export LETO_PATH="${LETO_PATH:-$HOME/leto/}"     # слэш в конце обязателен
for d in "$LETO_PATH"/*/; do
    git -C "$d" rev-parse --git-dir >/dev/null 2>&1 || continue   # Common/ и Console/ — не репозитории
    git -C "$d" fetch --prune origin || exit 1
    printf '%-14s %s\n' "$(basename "$d")" "$(git -C "$d" status -sb | head -1)"
done
```

## Правила

- `git status -sb` без `fetch` сравнивает с устаревшим `origin/main`: может не показать
  отставание. Сначала `fetch`, потом читать код.
- Есть `behind` — только `git merge --ff-only origin/main`. Разошлись или дерево грязное —
  остановиться и сообщить, конфликты автоматически не разрешать.
- Ветку задачи отводить от свежего `origin/main`, а не от снимка, полученного при старте.
- «Этого нет в репозитории» проверяется по сети: `git ls-remote origin main`, `gh api`.
  Пустой `find`/`grep` по локальному дереву говорит только о локальной копии.

## Отчёт

Четыре строки `<repo> <branch> <ahead/behind>`; если что-то подтянули или остановились —
сказать явно.
