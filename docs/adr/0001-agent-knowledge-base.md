# ADR 0001. База знаний агента: маршрутизатор и скиллы вместо одного файла

Статус: принято · Дата: 2026-11-26 · Задача: #120

## Контекст

`AGENTS.md` вырос до 295 строк и содержал четыре разных типа знания вперемешку:
инварианты архитектуры, процедуры (сборка, PR, доска, права токенов), текущее
состояние реализации и соглашения об оформлении. Файл читается целиком в начале
каждой сессии, поэтому:

- процедуры конкурируют за внимание с инвариантами, которые нужны всегда;
- раздел «Текущее состояние» (AppLoader, `dlclose`, `--user`) устаревает при первом
  же мёрже, и обновлять его никто не обязан;
- одна и та же проверка выполняется заново, потому что нет единой точки входа и
  негде зафиксировать, что она уже пройдена;
- знание про `LetoAPI` (замороженный ABI) и про игры в `leto-games` отсутствует
  вовсе, хотя ошибки там дорогие;
- текст ничем не проверяется: переименованный пресет или удалённый путь
  обнаруживается только чтением.

Проект состоит из четырёх независимых клонов без подмодулей. Это ограничение
важно: знание, положенное в `leto-console`, не видно агенту, который открыл
`LetoOS`.

## Решение

1. **`AGENTS.md` — маршрутизатор.** Только инварианты, карта и Definition of Done.
   Бюджет 120 строк, превышение — ошибка линтера.
2. **Процедуры — в `.agents/skills/<name>/SKILL.md`.** В контекст всегда попадает
   только `name` и `description`, тело — при вызове. Описание содержит ситуацию
   («Использовать, когда…»), иначе скилл никогда не сработает.
3. **Состояние реализации — не текст, а проверка.** `scripts/leto-check.sh`
   собирает цепочку и прогоняет `ctest`; `--full` дополнительно проверяет, что в
   `.so` нет `STB_GNU_UNIQUE` (иначе `dlclose` не выгружает игру).
4. **Справочник генерируется.** `docs/reference/presets.md` собирается из
   `CMakePresets.json` скриптом `scripts/gen_reference.py`, CI сравнивает результат
   с закоммиченным (`--check`).
5. **Решения — в `docs/adr/`.** ADR неизменяем: новое решение оформляется новым
   ADR, старый помечается вытесненным. Обновлять историю задним числом нельзя.
6. **База знаний проверяется в CI.** `scripts/ctx_lint.py` ловит несуществующие
   пути, пресеты, которых нет в манифесте, скиллы с непригодным `description`,
   превышение бюджетов и разъехавшиеся варианты пометки AI.
7. **Скиллы доставляются в соседние репозитории** скриптом `scripts/sync-skills.sh`;
   источник один — `leto-console`.

## Последствия

- Постоянный контекст сессии: ~110 строк вместо 295, процедура подгружается по
  необходимости.
- Устаревшая команда ловится на PR, а не через месяц при чтении.
- Цена: скиллы нужно синхронизировать в три репозитория, а при добавлении нового
  скилла — думать о триггерах, а не только о содержании. Потолок 12 скиллов:
  новый появляется вместо удалённого, иначе выбор перестаёт быть однозначным.
- Правило на будущее: агент повторил уже объяснённую ошибку второй раз — знание
  понижается до теста, линтера или скилла, а не остаётся абзацем.
