# AGENTS.md

Правила для AI-агентов и людей, работающих с LETO. Здесь только то, что нужно в
каждой сессии: инварианты, карта и определение готовности. Процедуры — в скиллах
`.agents/skills/`, они загружаются по необходимости, а не читаются целиком.

## Точка входа

Задачи — в issues `leto-console/leto-console`. Код разложен по независимым клонам,
которые должны лежать рядом в одной папке `$LETO_PATH` (подмодулей нет):

| Репозиторий | Роль |
| --- | --- |
| `LetoAPI` | замороженный C ABI: `LetoApplication_V1`, `LetoAPI_V1`, `AppBinHeader` |
| `LetoCore` | движок: отрисовка, сцены, инфраструктура игр |
| `LetoOS` | системный слой: `AppLoader`, `SystemSceneManager`, дисплей |
| `leto-console` | точка входа: `Core/Src/Application/System.cpp`, `main()` |
| `leto-games/*` | игры: `game-template`, `Battleship` — отдельная организация |

Клоны ничем не синхронизируются: локальное дерево может отставать, выглядя
исправным. Перед чтением кода и перед веткой — скилл `leto-sync`.

## Инварианты

- `LetoCore` не подключает заголовки `LetoOS`. `SystemSceneManager` объявлен в
  `LetoOS/include/System/`; заголовки, которым нужен системный слой, лежат в `LetoOS/include`.
- Приложение линкует только `LetoAPI` и `LetoCore`, `LetoOS` в игру не попадает.
  Системные части остаются в `LetoOS`, а не переносятся в `LetoCore` ради удобства игр.
- `LetoAPI` — замороженный ABI. Несовместимое изменение оформляется как новая
  версия (`V2`), а не правкой `V1`. Любая правка — через скилл `leto-abi`.
- `LetoAPI`, `LetoCore` и `LetoOS` собираются как `STATIC` на всех платформах, кроме
  `WIN32` с заданным `LETO_PATH`. Не переводить на `SHARED`.
- Приложение несёт собственную копию `LetoCore`. Дублирование состояния
  (`VirtualConsole`, `DrawFunctions::defaultFont`) — осознанное решение,
  воспроизводящее поведение прошивки. Не «унифицировать». Состояние хоста игра
  читает только через `LetoAPI` (например, `leto_api_v1->Font->FindFont`).
- `-fno-gnu-unique` обязателен и в хосте, и в игре: иначе glibc держит DSO
  замапленным и `dlclose` не выгружает игру.
- `GITHUB_TOKEN` и `LETO_GAMES_TOKEN` не печатать. Запись в `leto-console/*` —
  только `GH_PROJECTS_TOKEN`.

## Процесс, который легко забыть

- Ветка от свежего `origin/main`, имя `<номер-issue>-<краткий-слаг>`.
- В `main` не пушить. PR открывается только по явной команде. Мерж — только
  «Merge commit», не squash и не rebase. Ветка удаляется сразу после мержа.
- Любое сообщение от имени владельца начинается строкой, дословно:
  `Написано AI-агентом (OpenHands) по поручению владельца репозитория.`
  В сообщении коммита та же строка — последним абзацем. Одна формулировка на все
  типы сообщений, включая однострочные ответы в тредах ревью.
- Подробности веток, ревью, прав и мержа — скилл `leto-pr`; доска — `leto-board`.

## Проверка (Definition of Done)

Одна точка входа, а не набор команд:

```sh
./scripts/leto-check.sh          # затронутые репозитории: сборка + ctest
./scripts/leto-check.sh --full   # все четыре + проверка выгрузки .so
```

Не гонять полный прогон в цикле: итерация — сборка одного репозитория, `leto-check` —
перед коммитом, `--full` — перед PR. Задача готова, когда `leto-check` зелёный и
`python3 scripts/ctx_lint.py .` не даёт ошибок. Дальше не перепроверять.

## Карта

| Что | Где |
| --- | --- |
| `main()`, регистрация сцен, `--game`/`--user` | `Core/Src/Application/System.cpp` |
| Сцены и экраны | `Core/Inc/ProjectScenes/`, `Core/Src/ProjectScenes/` |
| Идентификаторы сцен | `Core/Inc/ProjectScenes/SceneID.hpp` |
| Скрипты локальной сборки | `scripts/` |
| Пресеты (источник правды) | `CMakePresets.json`; список отдаёт `cmake --list-presets` |
| Тесты | `LetoCore/Tests`, `LetoOS/Tests`; запускает их linux-пресет |
| Решения «почему так» | `docs/adr/` |

## Скиллы

| Скилл | Когда |
| --- | --- |
| `leto-sync` | перед чтением кода, перед веткой, «в репозитории этого нет» |
| `leto-build` | собрать цепочку или один репозиторий, пресеты, `LETO_PATH`, SDL2 |
| `leto-check` | перед коммитом, воспроизвести падение CI |
| `leto-run-game` | запустить консоль или игру, в том числе headless |
| `leto-pr` | ветка, коммиты, ревью, мерж, закрытие issue, права токенов |
| `leto-board` | статус задачи на доске `LETO Console` (GraphQL, не `gh project`) |
| `leto-new-scene` | добавить сцену, экран или пункт меню в консоль |
| `leto-abi` | правка `LetoAPI`/`LetoABI`, добавление `V2`, публичные структуры |
| `leto-new-game` | новая игра из `leto-games/game-template`, фикстуры загрузчика |

## Не трогать без отдельной задачи

- Сборка игр и `game-template` — отдельные репозитории; фикстуры для тестов
  загрузчика добавляются своей задачей, а не попутно.
- Termux на паузе: пресеты `termux-*` удалены, код под `#ifdef __TERMUX__` остаётся.
- Шрифты остаются в `LetoCore`; вынос в `LetoFont_V1` — отдельная будущая задача.

## Как расширять эту базу знаний

- Нужно в каждой сессии — сюда, но бюджет 120 строк: `scripts/ctx_lint.py` не даст
  превысить.
- Многошаговая процедура — новый скилл `.agents/skills/<name>/SKILL.md` с описанием
  «Использовать, когда…». Потолок — 12 скиллов; новый только вместо удалённого.
- Состояние реализации не описывать текстом: писать проверку в `scripts/` и
  запускать её в `leto-check`.
- Производное не хранить: список пресетов, целей и чеков спрашивать у инструмента
  (`cmake --list-presets`, `cmake --build --target help`, ruleset через `gh api`).
  Сгенерированный файл — это второй источник правды, который надо обновлять.
- Агент повторил уже объяснённую ошибку второй раз — знание понижается в тест,
  линтер или скилл, а не в абзац.
